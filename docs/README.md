# docs — 项目文档中心

## 职责

- 集中管理项目文档：架构设计、接口契约、部署、开发指南、日志 schema、变更记录；
- 文档与代码同步维护：接口变更必须同步更新 api.md 与对应模块 README。

## 维护

- 项目作者（单人开发）负责编写与维护。

## 文档清单

| 文档 | 内容 | 状态 |
| --- | --- | --- |
| ../README.md | 项目总览、功能特性、系统流程、快速开始、部署、开发约定 | 使用中 |
| quickstart.md | 本地开发快速开始（环境 / 初始化 / 命令 / 端口速查） | 使用中 |
| deploy.md | Docker 部署编排、管理后台、运维与常见问题 | 使用中 |
| api.md | 接口契约（权威文档） | 使用中 |
| architecture.md | 架构设计（链路 / 数据流 / 时延预算 / 关键决策） | 使用中 |
| logging.md | 结构化日志事件 schema（JSONL 指标） | 使用中 |
| CHANGELOG.md | 变更记录（开发全过程：契约演进、优化、修复） | 使用中 |

## 约定

- 接口字段变更 = 破坏性变更，需同步更新 api.md 并全链路联调；
- 每次变更在 CHANGELOG.md 追加记录；评测结果归档到 eval/reports/；
- 文档由作者本人维护，改动随 git 提交一起走（`docs` 前缀提交）。
